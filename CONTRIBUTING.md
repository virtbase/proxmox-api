# Contributing

Thanks for taking the time. This is a fork of
[UrielCh/proxmox-api](https://github.com/UrielCh/proxmox-api), maintained for
[virtbase](https://virtbase.com).

## Getting set up

```bash
bun install
bun run build
bun run test
```

Bun and Node versions are pinned in `package.json` (`engines`, `packageManager`)
and `.nvmrc`.

## Before opening a pull request

```bash
bun run check       # Biome lint and format
bun run typecheck
bun run test
bun run build
```

The `pre-commit` hook runs Biome over staged files and then the test suite, so
most of this happens on its own.

## Commit messages

Commits follow [Conventional Commits](https://www.conventionalcommits.org/), and
`commitlint` enforces it in a `commit-msg` hook and again in CI.

This is not a style preference: the release version and the changelog are
generated from these messages.

| Prefix | Effect on the next release |
| --- | --- |
| `fix:` | patch |
| `feat:` | minor |
| `feat!:`, or a `BREAKING CHANGE:` footer | major |
| `refactor:`, `docs:`, `perf:`, `build:` | listed in the changelog, no bump |
| `chore:`, `test:`, `ci:`, `style:` | no bump, hidden from the changelog |

## What not to edit by hand

Two paths are generated. Change the generator, not the output:

- `packages/api/src/model.ts`
- `docs/reference/endpoints/`

Both come from `bun run codegen`, and CI rejects a stale copy. See
[`packages/generator/README.md`](packages/generator/README.md).

`packages/api/CHANGELOG.md` is generated by release-please from commit
messages. The entry above the first release heading is historical and predates
that automation.

## Releasing

Setting the pipeline up, and the maintainer's side of it, is in
[MAINTAINING.md](MAINTAINING.md).

Nobody publishes by hand. Merging to the default branch keeps a release pull
request up to date with the pending version bump and changelog; merging *that*
tags the release, which triggers the npm publish with provenance.

## Updating for a new Proxmox release

Proxmox rewrites its published schema in place. A weekly workflow regenerates
against it and opens a pull request when the result differs. Review it for
**removed** endpoints and narrowed types — those break consumers — then merge.
It is committed as `feat!`, so it releases as a major version.

To do it by hand:

```bash
bun run codegen
```
